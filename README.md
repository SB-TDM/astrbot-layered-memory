# astrbot-layered-memory

AstrBot 的记忆插件集：**七层分层记忆 + 群友档案**。

给 AstrBot 补两块内置做不好的能力：

- **记忆没有时间维度** —— 内置只有「最近若干条对话」，三天前的闲聊和上周的约定一样重，而且越聊越大。
- **不记得人** —— 换个会话就忘了你是谁，也没有任何长期偏好记录。

两个插件可以一起用，也可以单独用。

| 插件 | 解决什么 |
|---|---|
| [`layered_memory`](plugins/layered_memory) | 把记忆按「内核 / 月 / 周 / 日 / 即时 / 原文」分层，越近越细、越远越粗，固定只注入约 1000 token |
| [`user_memory`](plugins/user_memory) | 给每个 QQ 号维护一份档案，自动抽取稳定事实、去重、定期压缩，并注入好感度 |

## 安装

```bash
cp -r plugins/* /path/to/AstrBot/data/plugins/
```

重启 AstrBot，然后在面板的插件配置页调参数。

依赖 AstrBot >= 4.29。`user_memory` 的好感度功能需要另外装 `astrbot_plugin_self_learning`，没装会自动跳过。

**装完要改占位符**（只影响权限判断）：

```bash
grep -rl "YOUR_QQ_NUMBER" plugins/ | xargs sed -i 's/YOUR_QQ_NUMBER/你的QQ号/g'
```

`layered_memory` 里这个号是「只有主人能改记忆内核」的判断依据，填错会导致自己用不了 `/记住`。

## layered_memory

### 七层结构

| 层 | 内容 | 生成时机 | 是否注入 |
|---|---|---|---|
| L1 内核 | 我是谁、对方是谁、什么关系、习惯 | 手动维护 | ✅ 每轮全量 |
| L2 月纪要 | 这个月的主线 | 每月 1 号 00:05 | ✅ 最近 1 条 |
| L3 周纪要 | 这周聊了什么 | 每周日 23:55 | ✅ 最近 1 条 |
| L4 日纪要 | 今天聊了什么 | 每天 23:50 | ✅ 最近 2 条 |
| L5 即时摘要 | 刚才在聊什么 | 每 20 轮 | ✅ 1 条 |
| L6 原文 | 原始对话 | 实时写入 | ❌ 只用于压缩 |
| — | **跨会话摘要** | 每次压缩后 | ✅ 1 条（可选） |
| L7 临时 | 当轮工作区 | — | 回复后丢弃 |

### 压缩与删除

```
每条消息 → 写入 raw（L6），顺手删掉 3 天前的原文
   ↓ 每 20 轮
L5 即时摘要（1–2 句）
   ↓ 每天 23:50
L4 日纪要（3–5 句）
   ↓ 每周日 23:55
L3 周纪要（4–6 句）
   ↓ 每月 1 号 00:05
L2 月纪要（5–7 句）
```

**删除策略**：

| 层 | 保留 |
|---|---|
| L6 原文 | **3 天，硬删** |
| L5 即时摘要 | 1 条，覆盖写 |
| L4 日纪要 | 永久（一年 365 行） |
| L3 周纪要 | 永久（一年 52 行） |
| L2 月纪要 | 永久（一年 12 行） |

### 跨会话摘要

每个会话的记忆是分开的（群里聊的和私聊聊的不混），但会额外注入一条**另一个会话的即时摘要**，避免换个场景就接不上话。

```
私聊里注入：  【另一个会话里刚才在聊】他们在说昨晚的比赛，BLG 输了
群里注入：    【另一个会话里刚才在聊】刚在私聊说面试挂了，可能心情不好
```

只带一两句摘要，不带原话和细节。默认只注入 2 小时内的，太旧的不带。

要严格分区的话，把 `cross_session_recent` 关掉即可。

### 关机补偿

如果 23:50 那一刻 AstrBot 没在跑，那天的纪要会漏。插件启动 10 秒后会检查一遍：

```
raw 里有哪些日期  −  daily 里已有哪几天  =  需要补的
```

有缺口就当场重新压缩。**只能补原文还在的日期**（3 天内）。

### 命令

| 命令 | 作用 |
|---|---|
| `/记忆层` | 查看各层内容 |
| `/记住 xxx` | 往 L1 内核追加一条（仅主人） |
| `/总结` | 立刻生成今日纪要 |
| `/周总结` | 立刻生成本周周纪要 |
| `/月总结` | 立刻生成本月月纪要 |

### 配置项

| 配置项 | 默认 | 说明 |
|---|---|---|
| `enable` | `true` | 总开关 |
| `raw_keep_days` | `3` | 原文保留天数 |
| `daily_inject` | `2` | 注入最近几条日纪要 |
| `recent_turns` | `20` | 即时摘要刷新间隔 |
| `core_max_chars` | `500` | 内核最大字数 |
| `daily_time` | `23:50` | 日纪要时间（HH:MM） |
| `weekly_time` | `23:55` | 周纪要时间 |
| `monthly_time` | `00:05` | 月纪要时间 |
| `backfill_enabled` | `true` | 启动时补生成缺失纪要 |
| `cross_session_recent` | `true` | 注入其他会话的即时摘要 |
| `cross_fresh_minutes` | `120` | 跨会话摘要的有效期（分钟） |

## user_memory

### 怎么工作

```
每条消息进模型前 → 把该用户的档案 + 好感度拼进 system prompt
回复生成后      → 后台调一次模型，抽取稳定事实，写回档案
```

注入的内容：

```
关于正在跟你说话的这个人（你以前记下来的，别当新信息问）：
- QQ 123456789，昵称 某个人
- 身份：上班族
- 技术栈：pywebview
自然地用这些信息就行，别复述，也别一条条念出来。

你对这个人的好感度是 62/100。按人设里的分档决定亲近程度。
```

### 特性

| 特性 | 说明 |
|---|---|
| 自动抽取 | 只记身份、职业、长期偏好、雷点，不记一次性情绪 |
| **不记称呼** | 「爸」「哥」这类称呼随时会改，记了会和人设打架 |
| 写时去重 | 归一化后相似度 ≥ 0.85 判重，保留较新的措辞 |
| 定期压缩 | 超 15 条压到 10 条；每周一 04:30 全量压一遍 |
| 好感度注入 | 从 `self_learning` 读，按 QQ 号取最高值 |
| 权限隔离 | 看别人档案需要管理员 |

### 命令

| 命令 | 作用 |
|---|---|
| `/记忆` | 看自己的档案 |
| `/记忆 <QQ号>` | 看别人的档案（仅管理员） |
| `/忘记` | 清空自己的档案 |
| `/压缩档案` | 立刻压缩自己的档案 |

### 配置项

| 配置项 | 默认 | 说明 |
|---|---|---|
| `enable` | `true` | 总开关 |
| `inject_profile` | `true` | 注入档案 |
| `inject_affection` | `true` | 注入好感度 |
| `extract_enabled` | `true` | 自动抽取 |
| `min_interval_seconds` | `300` | 同一号两次抽取的最小间隔 |
| `min_message_length` | `4` | 消息太短不抽取 |
| `max_facts` | `30` | 每人最多条数 |
| `similarity_threshold` | `0.85` | 去重阈值 |
| `compact_enabled` | `true` | 启用压缩 |
| `compact_threshold` | `15` | 触发压缩的条数 |
| `compact_target` | `10` | 压缩后保留条数 |
| `weekly_compact` | `true` | 每周全量压缩 |

## 两个插件怎么配合

| 层 | 谁负责 | 管什么 |
|---|---|---|
| 关系与设定 | `layered_memory` 的 L1 | 「他是我爸」「我有自己的想法」 |
| 具体事实 | `user_memory` 的档案 | 「他用 pywebview」「他喜欢猫」 |
| 近期经历 | `layered_memory` 的 L4/L5 | 「昨天面试挂了」 |
| 亲近程度 | `user_memory` 注入的好感度 | 0–100，决定语气分档 |

分工原则：**关系归记忆层，事实归档案层**。两者混在一起会互相覆盖。

## 调参经验（都是踩出来的）

| 想改什么 | 别这么写 | 应该这么写 |
|---|---|---|
| 回复更短/更长 | 规则里写「二十到四十字」 | 改示例句本身的长度 |
| 颜文字频率 | 「十条里带三次」 | 「只在接梗、被调侃时带」 |
| 让规则生效 | 写在提示词末尾 | 挪到最前面 |
| 改说话格式 | 只靠提示词 | 加一层发送前的代码整形 |

模型对**示例**的模仿力度大于对**规则**的服从，格式问题别指望提示词。
